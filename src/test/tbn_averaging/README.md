# 切线平均与 TBN 正交化

用同一块有共享顶点的弯曲网格，依次观察：不平均时的三角形接缝、平均后的平滑效果、平均和插值后的非正交误差，以及 Gram–Schmidt 修正。OpenGL 3.3 Core，沿用项目的 GLFW、GLAD、GLM、Shader；法线纹理在程序中生成，无额外图片依赖。

## 构建与运行

在项目根目录执行 PowerShell：

```powershell
cmake -S . -B build -A x64
cmake --build build --config Debug --target test__tbn_averaging --parallel
Push-Location .\bin\test\Debug
.\test__tbn_averaging.exe
Pop-Location
```

产物为 `bin/test/Debug/test__tbn_averaging.exe`，着色器复制到程序旁的 `tbn_averaging/`。Release 时将构建配置和路径中的 `Debug` 都改为 `Release`。`test_demos` 也会构建本示例。

## 先按这个顺序观察

默认四面板使用同一个相机、光源、几何体、UV 和平滑法线，只改变 T/B 的来源及修正方式。

| 面板 | 处理 | 观察重点 |
| --- | --- | --- |
| 左上：1 TRIANGLE T/B | 各三角形使用自己的 T/B | 高光出现折线、块状变化，沿三角形边界不连续 |
| 右上：2 AVERAGED T/B | 在共享顶点平均邻面的 T/B，分别归一化后插值 | 接缝消失或减弱，高光连续；方向仍可能存在小偏差 |
| 左下：3 AVERAGED BASIS ERROR | 展示平均版本的真实正交性误差 | 黄、红区域表示三根轴没有完全垂直 |
| 右下：4 GRAM-SCHMIDT | 对平均并插值后的基重新正交化 | 保持平滑连接，修正高光位置、形状的细微偏差 |

1. 先按一次 `N`，切到 `CONSTANT TILTED NORMAL`。这是统一的倾斜切线空间法线，消除了纹理花纹干扰，左上面的分块高光与右上的平滑高光最容易比较。
2. 按 `W` 叠加三角形线框，确认分块沿着网格边界。再按一次关闭。
3. 按 `E` 让四个面板都显示误差。平均版本仍有黄色区域；修正版本接近纯蓝色。再次按 `E` 返回正常光照。
4. 用 `2`、`4` 在同一大视图中切换平均与修正，观察高光的细微移动；`L` 可以让光源运动。按 `0` 回到四面板。
5. 再按 `N` 切到 `FLAT NORMAL - CONTROL`，三个光照面板应完全一致：此时切线空间法线为 `(0,0,1)`，结果只使用共同的 N。再按一次恢复波纹法线贴图。
6. `C` 切换更密网格。实际效果与网格曲率、采样密度有关，平均的收益和误差不应理解成固定程度。

正交化的光照改善通常比“从不平均到平均”更细微，符合教程中的 slightly off。热力图放大的是显示色阶，计算中没有人为放大或注入 TBN 错误。

## 1. 为什么平均：同一点不应因属于不同三角形而换一套方向

在 [mesh.h](mesh.h) 的 `Mesh::create()` 中，首先用位置边和 UV 差计算每个三角形的切线：

```cpp
T = normalize((edge1 * deltaUV2.y - edge2 * deltaUV1.y) / determinant);
B = normalize((edge2 * deltaUV1.x - edge1 * deltaUV2.x) / determinant);
```

曲面由平面三角形近似，邻面的方向不同。某个共享顶点 P，从三角形 A 一侧到达时可能使用 `T_A`，从 B 一侧到达时使用 `T_B`。即使 UV 连续、采样到相同的切线空间法线，`normalize(TBN * normalTS)` 也可能给出不同的世界空间法线，光照就会沿边界发生跳变。

本例按三角形在共享顶点的内角加权累加 T、B、N，再分别归一化。相邻三角形使用相同顶点属性，因此沿共享边插值的结果连续。GPU 顶点数据最后展开为三角形，便于保留面级 T/B；平均操作在展开前的共享顶点上完成。

仅应在同一平滑区域内平均。硬边、UV 接缝、镜像 UV 手性边界通常需要拆分顶点，不能把所有位置相同的顶点都合并。

## 2. 为什么分别 normalize 还不够

平均是向量相加，正交是向量之间的约束。多个正交坐标系逐列平均，通常不会得到新的正交坐标系。

例如下面两组基各自都正交：

```text
基 A：T=(1,0,0)，B=(0,1,0)，N=(0,0,1)
基 B：T=(0,1,0)，B=(0,0,1)，N=(1,0,0)
```

等权平均后分别归一化，T 的方向是 `(1,1,0)`，N 的方向是 `(1,0,1)`，两者点积变成 `0.5`，夹角只有 60°。归一化保证长度为 1，没有保证两根轴垂直。这个夸张的数字例子用于说明原理，实际网格的误差要小得多。

如果法线贴图给出倾斜法线 `(x,y,z)`，世界空间方向为 `normalize(x*T + y*B + z*N)`。非正交的基会改变这些分量组合后的角度，从而改变光照、高光的位置和形状。对结果再 normalize 只能改长度，不能恢复正确方向。此时也不能将 `transpose(TBN)` 当成严格的逆矩阵。

热力图显示归一化后三根轴的：

```text
E = max(abs(dot(T,N)), abs(dot(B,N)), abs(dot(T,B)))
蓝色：0；金色：0.05；红色：0.10 及以上
```

面板下方的数字是 **CPU 顶点处**的最大误差；热力图是 **GPU 插值之后每个片元**的误差，两者不会完全相同。插值本身也不保持正交。

## 3. 最终修正：平均后正交化，保留平滑和正确角度

关键实现位于 [assets/surface.fs](assets/surface.fs)：

```glsl
vec3 n = normalize(N);
vec3 t = normalize(T);
vec3 b = normalize(B);
float handedness = dot(cross(n, t), b) < 0.0 ? -1.0 : 1.0;

t = normalize(t - n * dot(n, t));
b = handedness * normalize(cross(n, t));
vec3 normalWS = normalize(mat3(t, b, n) * normalTS);
```

从 T 中去掉沿 N 的分量，得到垂直于 N 的 T；再用叉积重建同时垂直于 N、T 的 B。手性符号用于保留 UV 坐标系的方向。正交化放在片元着色器中，修正顶点插值带来的残余误差；仅在顶点着色器中做一次，并不能保证三角形内部仍严格正交。

平均负责平滑连接，正交化负责局部坐标轴相互垂直。只正交化每个独立三角形而不共享切线，仍然可能有接缝。生产资产还应保证运行时切线基与法线贴图烘焙器一致，本例不是完整的 MikkTSpace 实现。

## 实现选择与验证

为单独观察平均的影响，本例先将每个面的 T/B/N 正交化，再参与平均；原始 UV 导数中的 T/B 也可能因 UV 偏斜不垂直，这里先排除了那部分误差。模式 1 渲染时保留面级 T/B，但 N 和其他模式一样采用平滑法线，因此模式 1 的片元 TBN 也可能非正交。

曲面是半径随高度变化的一段旋转曲面。非均匀顶点间距、交替对角线使邻面差异更明显；所有阶段的网格一致，不会在“平均”模式下偷偷细分几何体。法线纹理使用线性 `RGB16F` 存储，模型变换为单位矩阵。

```powershell
Push-Location .\bin\test\Debug
.\test__tbn_averaging.exe --verify
Pop-Location
```

验证模式创建隐藏窗口，检查面级基正交、平均引入误差、修正后恢复正交；实际渲染并读回像素，确认不同处理会改变法线贴图光照，平坦法线对照的三个光照版本则完全一致。还检查密网格绘制和 OpenGL 错误。失败返回非零退出码。

当前粗网格测得：共享顶点的面切线差异最大约 `21.27°`；平均顶点最大点积误差约 `0.01509`，修正后约 `5.96e-8`。这些是本例的测量值，不是一般误差上限。

验证输出 `comparison.ppm`、`errors.ppm`、`constant_normal.ppm` 到 `bin/test/Debug/tbn_averaging/`，构建与预览产物均被 Git 忽略。
